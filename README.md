# 연구실 탐색 지도

성균관대학교 소프트웨어학과의 연구실을 관심 분야에서 출발해 탐색하는 학부생용 MVP입니다. React + TypeScript + Vite로 구현했으며 로그인 없이 로컬에서 실행됩니다. 기존 Gemini 탐색 도우미를 사용하려면 서버의 `GEMINI_API_KEY` 설정이 필요합니다. 후보 비교와 사전 구성된 RAG 체험에는 API 키가 필요하지 않습니다.

## 실행과 검증

Node.js 22.18 이상을 권장합니다. Windows PowerShell에서는 `npm.cmd`를 사용합니다.

```powershell
npm.cmd install
npm.cmd run dev
```

개발 서버가 표시한 로컬 주소를 브라우저에서 엽니다. 자동 검증은 다음과 같습니다.

```powershell
npm.cmd test
npm.cmd run build
```

## 실제 데이터의 범위

- `SKKU_CS_연구실_연구분야.csv`의 59개 항목을 모두 앱 탐색 목록에 반영했습니다. 이 중 53개가 `연구실`이고, 나머지는 CSV에서 구분한 교수 연구분야·연구소입니다. CSV 원본은 수정하지 않았습니다.
- 기본 정보(소속, 탐색용 분야 분류, 교수, 연구실명, 주요 연구 분야, 홈페이지, 출처, 학부연구생 모집 여부, 비고)는 CSV의 값을 따릅니다. 빈 분류와 모집 여부는 화면에서 각각 `미분류`, `미확인`으로 표시합니다.
- 탐색용 분야 분류가 `보안·소프트웨어공학`인 8개 연구실만 공식 연구실·대학 페이지를 추가 조사하여 연구 개요, 연구 질문, 방법, 공개 논문, 학습 주제를 제공합니다. 나머지 항목에는 확인되지 않은 상세 내용을 만들어 넣지 않습니다.
- 논문은 해당 연구실의 전체 목록이 아닌 탐색을 돕는 사례입니다. 논문 제목·연도·게재처와 원문 목록 링크를 함께 제공합니다. 최형기 교수 연구실은 공개 교수 논문 목록에서 최근 항목을 확인하기 어려워 2018년 발표를 `기존 연구 사례`로 명시했습니다. 이은석 교수 항목은 CSV에 연구실 홈페이지가 없으므로 성균관대학교 공식 연구자 페이지를 사용했습니다.
- 학습 주제는 연구를 이해하기 위한 안내일 뿐 공식 개설 과목·담당 수업·선수과목이 아닙니다. 확인되지 않은 수업과 모집 정보는 추정하지 않습니다. 자료 확인일은 앱에 표시됩니다.

## 탐색 흐름

1. 추천 결과 상위 4개를 먼저 보고 `관련 후보 더 보기`로 추가 확인합니다. 서로 다른 두 연구실만 담을 수 있으며, 하단 선택 영역에서 개별 해제와 비교 이동을 할 수 있습니다. 개인적인 선택 이유는 선택 입력이고 검색 키워드로 자동 작성하지 않습니다. 상세 연구 자료와 링크는 접힌 토글에 보존합니다.
2. `연구실 비교와 수업 탐색`은 두 후보를 3열·7개 항목 표로 비교합니다. 실제 담당 수업의 이름과 강의코드를 표시하고, 관련 과목·학습 주제와 구분합니다. 확인되지 않은 학기·학부/대학원 구분·추천 과목의 강의코드는 추정하지 않습니다. 전체 논문 제목·설명·링크와 강의 시간은 연구실별 상세 토글에서 확인합니다.
3. 실제 구현된 체험은 SecAI(구형준) 연구실의 `RAG 오염 공격과 방어` 하나입니다. 다른 연구실은 준비 중으로 표시하며 대신 연결하지 않습니다. 정상 → 공격 → 방어를 각각 실행하면 사전 구성된 답변 14일 → 30일 → 14일을 확인합니다. 단계 선택만으로는 실행·완료되지 않습니다. 세 단계 실행 후 관찰 메모 없이도 저장해 최종 정리로 갈 수 있습니다. 4주 프로젝트와 사전 공부는 접힌 선택 항목입니다.
4. 기존 `내 탐색 정리하기` 레이아웃을 유지합니다. 새 체험 주제·실행 상태·메모·심화 계획·공부 선택은 기존 탐색 결과와 Markdown에 연결됩니다. 기록과 도우미 대화는 현재 브라우저의 localStorage에 저장되며 다른 기기와 동기화되지 않습니다.

탐색 도우미는 기존 `/api/chat` → 서버 Gemini 연결을 유지합니다. 모든 페이지에서 대화가 이어지고, 현재 관심·후보·체험 주제·실제로 실행한 단계·공부 선택을 전달합니다. `src/chat.ts`의 규칙 기반 응답은 별도로 보존하여 키 없이 자동 검증할 때 사용합니다. 브라우저 검증에서는 API 경로를 이 응답으로 대체하여 외부 유료 API를 호출하지 않습니다. 최신 정보는 연구실 또는 대학 공식 페이지에서 다시 확인해야 합니다.

CSV를 수정한 뒤에는 `src/catalog.ts`도 같은 행·열 순서로 갱신해야 합니다. 교수나 연구실 명칭이 바뀌면 선택 기록의 ID도 달라질 수 있으므로, 기존 브라우저 기록의 호환성을 확인하세요. 논문이나 모집 정보를 갱신할 때는 공식 출처와 확인일을 함께 검토하세요.

## 현재 제한

개별 연구실의 실시간 공지와 최신 모집 여부, 미확인 개설 학기, SecAI 외 연구실의 체험은 제공하지 않습니다. 구형준·최형기 교수님의 담당 수업과 시간은 기존 제공 자료를 그대로 유지합니다. 관련 과목 추천은 기존 학습 주제에 기반하며 확인된 공식 개설 과목으로 꾸미지 않습니다. RAG 문서·답변은 사전 구성된 교육용 예시로 논문 재현이나 실측 성능이 아닙니다.

이전 저장 기록의 관심·선택·개인 메모·실험·채팅은 보존합니다. 세 곳 이상 선택한 이전 기록도 임의로 자르지 않으며, 두 곳으로 줄여야 비교할 수 있습니다. 이전 RAG 단계 선택에는 실행 증거가 없어 완료로 추정하지 않고 재검토를 표시합니다. `src/algorithms.ts`의 BFS/A*와 과거 실험 형식도 호환성을 위해 남겨 둡니다.

## 이번 수정의 검증

핵심 테스트는 후보 수 제한, 개인 이유 보존, 구현된 주제만 연결, 순서에 따른 실제 단계 실행, 이전 저장 형식 호환성을 확인합니다. 브라우저 검증은 전체 이동 흐름, 3열 비교와 강의코드·상세 토글, 14일→30일→14일, 메모·심화 선택 복원, 챗봇 문맥·대화 유지, Markdown 다운로드, 데스크톱·모바일의 선택 영역 겹침과 가로 넘침을 확인합니다.

별도로 Playwright를 설치하고 개발 서버를 실행한 뒤 검증할 수 있습니다. 기본 브라우저는 Windows Edge입니다.

```powershell
npm.cmd install --no-save playwright
node --experimental-strip-types tests/browser-smoke.mjs
```

개발 서버가 다른 포트를 사용한다면 `TEST_BASE_URL`을 지정하세요. 기존 4페이지와 기본 스타일은 유지했습니다.

## 4페이지 다음의 새 페이지: 내 탐색과 다음 일주일

기존 4페이지의 `내 탐색과 다음 일주일 →` 버튼으로 5페이지에 들어갑니다. 앞의 네 과정 카드는 기존 페이지에서 유지하고, 새 페이지에서만 숨깁니다.

- 전체 너비의 탐색 흐름 지도: 관심, 후보 두 곳, 키워드 근거와 개인 선택 이유, 연구 문제·방법의 차이, 저장한 과목, 연결된 체험과 실제 실행 상태, 관찰과 기존 의견을 표시합니다.
- 방향 선택: 더 알아보기 / 두 연구실 비교 / 기초 이해. 진입만으로 방향이나 계획을 확정하지 않습니다.
- 브라우저 로컬 날짜를 기본 시작일로 사용하는 7일 일정. 가능한 날짜와 하루 15·30·60분, 익숙한 정도를 바탕으로 최대 3개 활동을 생성합니다.
- 기존 `/api/chat`과 서버 Gemini 연결을 재사용합니다. `mode: plan` 요청에는 기존 자료의 식별자만 허용하고 서버와 브라우저 모두 결과를 검증합니다. 외부 검색 API나 캘린더 연결을 추가하지 않습니다.
- 활동 제목·날짜·시간 직접 수정, 완료 체크, 한 줄 메모를 지원합니다. AI 조정은 미완료 활동의 수정안을 보여주며 `계획에 반영하기`를 눌러야 적용됩니다. 완료 활동과 최신 메모는 보존합니다.
- 일반적인 도우미 질문은 계획을 변경하지 않습니다. 기존 대화를 공유하고 현재 계획과 선택한 활동을 문맥으로 전달합니다.
- 방향·후보·체험이 바뀌어도 기존 계획은 유지합니다. 이전 탐색 기록을 기준으로 만든 계획에는 갱신 안내를 표시합니다.
- 계획 없이 탐색 결과만 저장할 수 있습니다. 전체 복사·Markdown 내보내기에 탐색 근거, 개인 의견, 자료 링크, 계획, 완료 상태와 메모를 포함합니다.

저장 형식은 버전 4이며 버전 1~3의 관심·선택·의견·실험·대화를 유지합니다. 날짜/자료 식별자/시간 등 검증에 실패하거나 API 호출이 실패하면 기존 계획을 유지하며 재시도할 수 있습니다. AI 계획 생성과 실시간 도우미 답변에는 기존 서버의 `GEMINI_API_KEY` 및 모델 설정이 필요합니다. 키가 없을 때 AI가 생성한 것처럼 임의 계획을 만들지 않습니다.
