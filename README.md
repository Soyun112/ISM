# 연구실 탐색 지도

학부생용 연구실 탐색 해커톤 MVP. React + TypeScript + Vite로 구현했고, API 키나 로그인 없이 동작합니다. 기존 `SKKU_CS_연구실_연구분야.csv`는 그대로 보존했으며 앱 데이터로 사용하지 않습니다.

## 실행

Node.js 22.18 이상 권장 (개발 환경: 24.18).

```powershell
npm.cmd install
npm.cmd run dev
```

표시되는 로컬 주소를 브라우저에서 엽니다. PowerShell 실행 정책에 영향을 받지 않도록 `npm.cmd`를 사용합니다.

```powershell
npm.cmd test
npm.cmd run build
```

## 구현

- 네 과정 이동, 태그 기반 추천 근거, 다중 후보 선택·이유 작성, 상세 비교
- 가상 교수 담당 수업과 연구 관련 과목 구분, 현재 미확인·과거 학기 표시, 과목 저장
- 실제 BFS/A* 길찾기: 장애물 편집, 예제·빈 지도·막힌 지도, 경로와 탐색 영역 비교
- 실험 당시 지도·후보·예상·관찰·알고리즘 결과 보존 및 불러오기
- 준비 기록 작성, 요약 복사·Markdown 다운로드, 탐색 지도
- 하나의 공통 데모 챗봇, 단계별 질문 예시, 기록 유지
- 버전이 있는 localStorage 저장, 손상 데이터 복구, 후속 기록 재검토 표시, 확인 후 전체 초기화
- 키보드 입력과 버튼, 반응형 레이아웃 및 모바일 도우미 드로어

탐색 칸 수는 처리 목록에서 꺼낸 칸 수입니다. 시작점과 도달한 목적지를 포함합니다. 모든 이동 비용은 1이며 A*는 일관적인 맨해튼 거리 휴리스틱을 사용합니다. 경로 길이는 이동 횟수입니다.

## 콘텐츠 교체

| 파일 | 변경 내용 |
| --- | --- |
| `src/content.ts` | 서비스명, 과정 문구, 키워드, 질문 예시, 체험 메타데이터 |
| `src/data.ts` | 연구실·교수·프로젝트, 담당 수업과 관련 과목, 출처 표기 |
| `src/recommend.ts` | UI와 분리된 태그 추천 로직 |
| `src/algorithms.ts` | 길찾기 구현과 예제 지도 |
| `src/chat.ts` | 데모 응답과 향후 API 연결 인터페이스 |
| `src/store.ts` | 저장 형식·검증·재검토 처리 |
| `src/main.tsx`, `src/style.css` | 화면 및 스타일 |

실제 데이터를 넣을 때 안정적인 연구실·과목 ID를 유지하고 출처와 확인 날짜를 실제 검증한 정보로 교체하세요. 현재 모든 연구실·과목·프로젝트는 가상이며 출처 URL은 만들지 않았습니다.

## 이후 AI 연결

`src/chat.ts`의 `generateReply(question, context)`를 실제 응답 함수로 교체합니다. 현재 과정·관심·후보·저장 실험·준비 기록이 전달됩니다. API 비밀 키는 브라우저 코드에 넣지 않고 별도 서버에서 처리해야 합니다.

## 범위 및 제한

언어·시각·사용자 연구 체험은 준비 중입니다. 배포, 회원가입, 결제, 크롤링, 실시간 교수·수업 정보, 외부 AI 연동은 이번 범위에 포함하지 않습니다. 기록은 현재 브라우저에 저장되며 기기 사이에 동기화되지 않습니다. 손상되거나 지원되지 않는 저장 형식은 안전한 초기 상태로 복구합니다. 편집 중인 미저장 지도·예상·관찰은 새로고침 후 복원되지 않으므로 ‘실험 결과 저장’을 눌러 보관하세요.

## 시연 확인 순서

1. ‘길찾기’ 입력 → 후보 추천 → 탐색·로봇 연구실 선택 → 선택 이유 작성
2. 연구 비교 → 관심 과목 저장 → 비교 확인 → 체험
3. 예상을 입력하고 비교 실행 → 관찰 입력 → 실험 저장
4. 준비 기록 작성 → 다음 행동 선택 → 저장 → Markdown 다운로드
5. 새로고침 후 후보·과목·실험·준비·채팅 기록 확인
6. 첫 과정에서 관심 변경 → 탐색 지도에서 후속 과정 재검토 상태 확인
7. 경로 없는 지도 실행 → 두 결과의 경로 없음 확인 → 예제 재실행

자동 검증은 다양한 지도의 최단 경로 일치·유효성, 막힌 지도, 저장 복원·손상 복구, 재검토 시 기록 보존, 추천 근거, 챗봇의 읽기 전용 동작에 집중합니다.

구현 시 타입 검사·프로덕션 빌드·핵심 테스트 5개와 Edge 기반 브라우저 시연 검증을 통과했습니다. 브라우저 검증은 전체 흐름, 새로고침 복원, 채팅 유지, 막힌 지도, Markdown 다운로드, 후속 재검토 상태, 390px 화면의 가로 넘침을 확인했습니다.

브라우저 검증을 다시 실행하려면 개발 서버 실행 후 별도 터미널에서 다음 명령을 사용합니다. 이 검증 도구는 앱 실행 의존성에 포함하지 않았으며 Windows 기본 Edge 경로를 사용합니다.

```powershell
npm.cmd install --no-save playwright
node tests/browser-smoke.mjs
```
